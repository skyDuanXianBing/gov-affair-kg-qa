# 需求规格说明书 — 全量节点向量化（问答实体链接正式修复）

> 创建：2026-08-09（晚）· Lead 会话 · Spec 级别：STANDARD
> 上游：`HANDOFF.md` §三待办1；`.pi/specs/2026-08-09-deepseek-qa-chain/task-b-solver-report.md` §4 RC2；`.pi/specs/2026-08-09-pilot-v02-reload/v02-reload-report.md`

## 1. 目标

对 Neo4j `govaffair` 库（v0.2，107,068 节点）全量节点生成 `_name_vector`（bge-m3 1024 维，本地 ollama），使 KAG 实体链接的向量检索路径对 Affair/Material 等全部类型生效，从而移除问答链路中 `exclude_types: Material` 的变通配置。

## 2. 方案（已调研 KAG 源码）

- 组件：`BatchVectorizer`（kag.builder.component.vectorizer.batch_vectorizer，注册名 `batch`）——为 SubGraph 节点的 name 属性生成 `_name_vector`（从服务端 schema 读取需向量化的属性，`_init_vec_meta`）。
- 挂载：`DefaultStructuredBuilderChain(mapping, writer, vectorizer=...)`（default_chain.py build()：mapping >> vectorizer >> writer），配置段 `chain_vectorizer`（type: batch + vectorize_model bge-m3）已在 `kag_config.yaml` 存在。
- 执行：indexer.py 增加 `--vectorize` 开关（additive，默认行为不变）；**只重跑 12 个节点文件**（`--only` 节点类型，不跑边文件，图中已有边不受影响），节点按 SPG upsert 幂等重写并携带向量。
- 前置：清 `builder/ckpt/`（组件级 diskcache 会跳过已写 chunk，必须清空才能让全部节点重新过链）。
- 看护：复用自愈包装思路（CPU 冻结 5 分钟 kill -9 重启，ckpt 续跑），预计 1~1.5 小时。
- 已知盲区：概念父节点（"行政权力"/"法人"，由 isA 边导入创建，不在节点 CSV 中）不会生成向量，文本兜底可覆盖，可接受。

## 3. 验收标准

- V1：小样试跑（`--only AffairType`）后，`_name_vector` 节点数 ≥ 8（9 个 AffairType 中除无 name 者），且向量可被 OpenSPG 搜索接口命中（probe_search.py 同款验证）。
- V2：全量完成后 `_name_vector` 节点数 ≈ 107,066 −（无 name 节点数）− 2（概念父节点），覆盖率 > 98%；抽查各类型均有向量（Affair/Material/ProcessStep/LegalCitation 等）。
- V3：问答回归：移除 `exclude_types: Material` 变通后，Q1（申领居住证材料）实体链接走向量路径命中 Affair 并落地；Q2（食品经营许可流程）重跑；补测"法律依据"类提问（v0.2 新解锁）。
- V4：0 indexer failures（容忍与 v0.2 灌图相同的"幻影失败"并核验无数据丢失）。

## 4. 风险

- ollama 本地 embedding 大量请求：bge-m3 已在跑，无计费；若 ollama 崩溃，重试/重启自愈。
- 节点重写期间 OpenSPG server 负载高（与灌图相同量级，已证明可行）。
- schema 若 name 属性无向量索引则向量不生成（小样试跑立即暴露，需查 schema 配置）。
- 执行中断：ckpt 续跑（本次清空后从头，中断后靠组件级 ckpt 续）。
