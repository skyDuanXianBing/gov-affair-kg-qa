# 需求规格说明书 — DeepSeek 接入与问答链路验证

> 创建：2026-08-09 · Lead 会话 · Spec 级别：STANDARD
> 上游文档：`HANDOFF.md` §三 待办 1、4（必读）；`kg/deploy/README.md`（运维约束）

## 1. 目标

将 GovAffair 项目的 chat 端点从 mock_llm 切换为真实 DeepSeek API，并基于真实端点验证 KAG 问答/召回链路（solver）在 1 万条试点图谱上可用。

## 2. 范围

### 2.1 本次任务内

- **任务 A（DeepSeek 接线，HANDOFF 待办 1）**
  1. 直连（**不走代理**）调用 DeepSeek `/models`，从环境变量 `deepseekapi` 取 key，确认可用 model id（优先 flash 变体，HANDOFF 提到 "v4 flash"）。
  2. 编辑 `kg/pilot/GovAffair/kag_config.yaml`：`chat_llm` 段切换为 DeepSeek 真实端点（type: maas，base_url: https://api.deepseek.com），更新文件头注释（去掉"key 无效"过时描述，记录实际接入日期与 model id）。
  3. `knext project update` 通过。
  4. 冒烟：真实 `/chat/completions` 调用成功（中文问答一句话即可）。
- **任务 B（问答/召回链路验证，HANDOFF 待办 4）**
  1. 摸清 `kg/pilot/GovAffair/solver/` 配置与 KAG solver 执行方式。
  2. 对 1 万试点图谱跑 2~3 个自然语言问题（如"办理居住证需要什么材料"类），确认召回（图检索/向量召回）+ LLM 生成全链路返回合理答案。
  3. 记录验证证据（命令、关键输出、trace）。

### 2.2 明确不做

- **不清空/重建 Neo4j**（v0.2 灌图 = HANDOFF 待办 2，涉及删除现有图数据，需用户单独确认）。
- 不动 `openie_llm`（保持 mock）：本项目走结构化建图路线，builder 不做 LLM 抽取；若任务 B 发现 solver 某组件实际依赖 openie_llm，子代理须**停下回报**，不得自行切换（涉及真实 API 计费）。
- 不动原始数据（`data/个人服务`、`data/法人服务` 只读）、不动 docker compose 与已运行容器、不做全量建图。
- 不在任何文档/日志/报告中写入完整 API key（只写"取自环境变量 deepseekapi"或末 4 位脱敏）。

## 4. 验收标准

### 任务 A
- A1 `curl https://api.deepseek.com/models`（直连、带 key）返回模型列表，报告中写明所选 model id 及理由。
- A2 `kag_config.yaml` 中 `chat_llm` 指向 `https://api.deepseek.com`，api_key 从环境变量读取（yaml 中明文 key 可接受但**报告与 git 可见文档中不得出现完整 key**）；注释头更新。
- A3 `knext project update` 成功（enable_check 可开，真实端点应能通过连通性校验）。
- A4 通过 KAG/OpenAI 兼容方式对 DeepSeek 发一次真实 chat completion，返回正常中文内容。

### 任务 B
- B1 报告中说明 solver 的启动方式与所用配置。
- B2 至少 2 个自然语言问题端到端跑通：有检索/召回痕迹（引用到图中节点或 chunk），且最终答案由真实 DeepSeek 生成（非 mock 输出）。
- B3 若链路因缺失组件（如 solver 依赖 openie/索引未建）失败，明确记录根因与所需前置条件，不盲修。

## 5. 风险与注意

- DeepSeek 调用产生真实计费：冒烟次数控制在个位数，不做批量测试。
- `knext project update` 失败时检查 enable_check、base_url 是否带 `/v1` 后缀（DeepSeek 兼容 OpenAI，maas 类型通常 base_url 不带 /v1 亦可，以实测为准）。
- 路径含中文，已实测无影响。
- 冒烟/验证产生的新文件写到 `kg/pilot/` 或本 spec 目录，不写进 `data/`。
